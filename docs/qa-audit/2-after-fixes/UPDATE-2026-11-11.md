## New finding: release builds accepted any TLS certificate (fixed)

**Severity: high.** Eleven HTTP clients in the app set `badCertificateCallback = (cert, host, port) => true`. That replaced the release-mode check in `lib/core/config/ssl_config.dart`, so **release builds accepted any certificate**. Anyone on the same Wi-Fi (or a hostile hotspot) could read or change the app's traffic: passwords, tokens and ticket data.

Files: `lib/services/api_service.dart`, `customer_profile.dart`, `customer_edit_profile.dart`, `customer_home_screen.dart`, `customer_ticket_modal.dart` (2 places), `admin_create_ticket_page.dart`, `end_user/edit_profile.dart`, `profile_screen.dart`, `home_screen.dart`, `end_user/ticket/ticket_modal.dart`.

**Fix:** the lines are removed. Debug builds still accept self-signed certificates through `ssl_config.dart`; release builds now reject bad ones.

**Retest:** on a release build, sign in, open home, profile, edit profile and create a ticket as customer, end user and admin. All should work normally against the real API. (They would fail only if a server's certificate is invalid, which browsers would also reject.)
